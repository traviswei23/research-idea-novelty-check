# ARIS 查新与独立复核

用这份规程回答“别人是否在同等条件下完成了我声称的新东西”。研究者只要求比较给定论文或当前无法外检时，仍可完成逐文对照，将未运行的查询和未完成的复核留在报告里。此页将 ARIS 原版及其核验、审查规程改写为不同学科可直接采用的操作。[上游查新入口](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/skills/novelty-check/SKILL.md)

## 1. 把题目固定成若干可被推翻的主张

让作者用一两句写出方案和声称的新意。按问题、核心操作、产生的现象或发现、成立条件拆分，通常三至五条；简单提案可能只含一条。给每条主张编号。把能直接推翻它的前作应具备的对象、输入、机制、使用条件和输出写在同一行。预期改善写成待验证效果。对于“没有人这样做过”，先确定作者指哪一个操作、什么时间以前和什么范围。保持这个版本，后续更改主张另记日期和理由。

## 2. 每个主张至少执行三种实质不同的查询

| 查询 | 如何取得新线索 | 需要记什么 |
|---|---|---|
| 同问题、不同名字 | 用旧称、同义词、缩写及另一研究群体的叫法找同一任务。 | 哪篇已知工作理应被找回，是否实际找回；漏掉时调整一项限制并重跑。 |
| 同机制、不同场景 | 去掉新方法名和领域标签，改搜动作、方程、测量量、信息来源或操作次序。 | 近邻是否实际执行了核心操作，还是只建议今后尝试。 |
| 最强替代或反方 | 用朴素基准、失败模式、相反结论、同类组合或最强竞争者的术语查。 | 哪个候选最可能已包含本主张，以及必须打开哪一节才能判断。 |

对各主张把真正运行的词组分别投向可访问的跨学科索引和本领域主要发现渠道，沿关键论文的参考文献及后续引用追查，并用出版社或正式仓库核对论文。按任务覆盖索引、学科库、近期会议、期刊在线优先和预印本，注明理由与不可用的来源。主检索保留早期基础工作；再从判断截止日向前**滚动六个日历月**，查本领域的近期预印本或在线首发。适合 arXiv 的领域应纳入该库。区分首次公开、期刊正式发表和后续修订，注明确切起止日期。用户给定历史截止日时按该日回溯。数据库日期定义不同，要核实最可能改变优先次序的文献时间。

记录每轮“主张 ID｜查询意图｜数据库和字段｜实际查询式｜执行日、限制与截止日｜纳入或排除的文献 ID 与理由｜失败和下一轮”。离线时将三条式子放在待执行栏；变更年份、轻微改词或重复跑同式不增加查询类别数。[原文的多源与近期检索](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/skills/novelty-check/SKILL.md#L39)

## 3. 分别核实论文身份与重合证据

对进入最近前作表的每篇论文分配 P 编号。检查正式记录是否匹配题名、作者、版本和时间；有 DOI 或预印本编号时对照标识符。歧义较大的模糊题名匹配只能提出候选；继续回到原始出版页，核实具体篇目。然后查方法、理论推导、图表、实验条件和补充材料，保留位置。真实存在的论文也可能没有做被声称的工作。

如环境已安装受信任的 ARIS，原工具在上游仓库根目录的 `tools/verify_papers.py`，支持 `--input papers.json --output verified.json`。输入是数组，每项含稳定 `id`，按可得性提供 `arxiv_id`、`doi`、`title`。它按标识符分流，分批查询 arXiv，可能用 Crossref DOI 或 Semantic Scholar 题名匹配；有 arXiv 标识的条目并不保证依次再查另外两库。返回 `verified` 表示文献存在得到支持，`unverified` 表示适用查询未匹配，`verify_pending` 表示暂时故障导致未决，`error` 提示输入等问题。遇到限流或超时，按查询层分别留痕，不把待处理文献记为虚构。这里未随附该脚本。脚本缺失或运行失败时保留未核纪录，若已从原始出版记录逐项核实，可另列手工证据和确切范围；不要登记为脚本已通过。[上游 CLI 与状态](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/tools/verify_papers.py#L17) · [具体分流实现](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/tools/verify_papers.py#L467) · [引文核实规程](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/skills/shared-references/citation-discipline.md#L105)

给每个“主张 × 前作”单独定性。**直接覆盖**要求前作已在必要条件下实施了同一关键操作或证明了同一结论。**部分覆盖**点明已知部分及哪一项机制、实验条件或发现仍可能构成增量。**邻近或并行**记录可学习或需关注的竞争工作，并行研究自身不足以要求撤题。**待核**用于身份、日期、全文条件或解释不足的条目。多个已知组件的组合仍需查组合本身、同资源朴素对照与非平凡效应；已知方法和可能的新发现可得不同判定。严禁以匹配轴数或自评分代替近邻原文。

## 4. 给独立审查人一个不含预设结论的材料包

**材料包模板**

| 段落 | 填写内容 |
|---|---|
| 任务与范围 | 调查截止日、当前主张版本、作者待决定什么、哪些渠道未覆盖。 |
| 主张表 | C 编号、原始表述、机制、必要条件、足以证伪的前作应具备什么。 |
| 近邻卡 | P 编号、稳定来源、版本、已核身份或待核理由、实际读到的段落或图表位置、限制。 |
| 检索记录 | 每项 C 对应的查询、来源、最近六个月覆盖和已知种子召回；区分待执行。 |
| 审查任务 | 移交原始证据与真实不确定处，不透露作者或初筛者想获得哪一档结论。 |

在用户授权和实际环境允许时，用新的审阅上下文独立检查，优先选择与执行者不同模型家族的实际后端。可由另一名独立研究者直接审查，注明为人工意见。未授权外发的未发表构想保留在可用的本地渠道。无法调度第二位审查者时，可先自行从反方重查，但须标作作者自查。若接受指定后端且其调用失败，不静默切换。将可交给用户或其他研究者的独立审阅材料包保留在交付中。

**可直接交给评审人的提示词**

> 逐条审阅材料包中的 C 编号。先用对该主张最不利的公开工作检验它，把直接对应的 P 编号、位置、版本和必要条件写出来。尝试用传统名字重述新方法，给出一个朴素解释，并检查两者在同一输入、资源与输出下是否仍可分辨。找不到足以推翻的已核前作时，指出哪一步仍未验证。分别判断方法、应用条件与发现，不把尚未验证的效果视作事实。逐项返回覆盖程度、最强依据、未解决的分歧、建议保留或撤回的确切句子，以及什么新证据会改变判断。最后列出你实际审完的 C 编号和未完成项。

资料很长时，把材料包保存在用户允许的工作区，通过授权渠道提供文件或关键原始证据，并确认接收方确实能读取。审阅前后核对原始 C 编号，处理评审者指出的漏搜和条件差异；有争议时展示双方证据，并指明怎样解决。[评审后端、身份与完成条件](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/skills/shared-references/reviewer-backends.md#L111)

## 5. 标明是谁查的、查了什么、结论为何改变

记录调用时间、主张版本、执行者与审查者身份、如何得到实际模型或人工身份、是否独立上下文、调用完成状态、审过哪些 C 编号、审阅意见及纳入或驳回理由。请求的模型、工具名、会话标签均不可冒充已返回的模型身份。已知同家族的独立会话可给暂定意见；跨家族须有实际身份、任务成功完成且范围覆盖的证据，区分得到审查与评审赞同。身份未明、截断、超时、排队、部分未审和未调用各按实标记，保留已有证据。不要把重复提示同一模型称作独立交叉验证。

经授权完整留痕时，保存移交版本、原始回复和调用元数据，让另一位研究者能重建结论。敏感材料可仅存元数据与可核查的本地引用；用户关闭留存时尊重设置，报告中标注可复核程度。上游 `tools/reviewer_route.py` 和 `tools/save_trace.sh` 可在已安装 ARIS 时使用；本独立技能也可用普通报告与文件记录。不要把未执行的调用填入日志。[评审路由](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/tools/reviewer_route.py#L57) · [留痕方式](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/skills/shared-references/review-tracing.md#L441) · [上游留痕实现](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/4ba94ae2a1c1fbbb14858750dd8764cabf6c28bd/tools/save_trace.sh#L302)

**结论格式**　“C 编号｜最近似的已核前作与位置｜已覆盖部分｜仍能区分的差异｜证据与审查状态｜下一步”。强烈建议撤回某条创新表述时，必须点名实际覆盖它的前作及对应证据；挂保留意见时写出差异薄弱的具体原因。结论只涵盖本次检索和审查范围。若没有直接前作却覆盖不全，把下一条最有信息量的查询交给研究者。
