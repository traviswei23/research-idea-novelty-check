# 从主张到可复查的检索

## A　检索范围和基准

写明作为判断基准的日期（今天、提出点子的日期或投稿日）。优先权问题按最早可核实的公开日期排序；可行性与可信度另按研究质量判断。限定领域、语言、文献类型和数据库须说明原因。用户若关心专利、标准、产品或未公开工作，要分别记录能实际查到的来源。论文查新不能代替专利法律判断。

建两组已知论文。一组用于起草术语，另一组作为独立挑战样本，测试查询能不能找回它。没有已知种子时从权威综述或用户给出的最接近论文启动，并注明尚无独立找回测试。搜不到应有论文时，分别检查索引收录、同义词、字段、时间和布尔表达式；修好后重跑受影响查询。只通过题名搜回的种子记录为定点找回，不算通用检索式通过。

## B　查询生成提示

> 以编号主张为输入。先用不含本文自造名词的语言复述要查的运算、约束和输出。分别给出最近似技术的旧叫法、竞争机制的术语、邻域对同一操作的表述。为每组给出能搜到它的查询和一条容易被误收的情形。列出一个你预计会被命中的已知条目。暂时遮掉性能形容词，避免只找支持该主张的工作。

先宽后窄，围绕下列不同问题组合，不把所有词塞进一个 AND 式。

| 想找什么 | 查询起点 | 何时换路 |
| --- | --- | --- |
| 相同任务、不同名称 | 问题词 × 条件同义词；补中英文、缩略词与老术语 | 已知前作无法找回，拆开限制词 |
| 同一机制、不同用途 | 动作或数学对象 × 原理词，去掉应用名；用结果的形式或测量量反搜 | 关键词相近但核心动作不同，改用操作动词、方程或数据流 |
| 基础和近期工作 | 代表性综述中的术语树、关键研究者或具名基准、预印本更新 | 年代集中，分别无时间下限查基础工作和按报告日查近期结果 |
| 不利证据和替代解释 | 方法 × 失败、限制、反例、简单基线、复现或无效结果 | 找不到反例时反转命题，用竞争机制本身检索 |
| 引文网络和技术来源 | 最近似论文的参考文献、后续引用、同一组作者早期稿；具体装置或算法可核对正式文档 | 新论文反复指向同一未读出处，优先读该出处和相关附录 |

可用服务按任务选择。用跨学科索引查术语与引用，用学科数据库和出版社核验原文，涉及近期成果时补预印本。只有 arXiv 时写明只覆盖相应预印本。快速初筛只用 Consensus 时，可按已有研究、直接方法、相邻条件、相反证据、综述做四至五次定向查询。OpenAlex 可逐批筛候选并保留游标和候选编号。模型标出的高威胁匹配要查原文。关键渠道均无法查询时，交付材料内对照及待执行检索式。

## C　运行、筛选与更新

检索日志每行为“查询编号｜主张编号｜数据库/检索字段｜**实际执行**的原式｜执行日和限制｜返回/检查/纳入数｜错误、分歧或下一轮理由”。平台未给出总数时记“未提供”。多个来源的原始命中数不能相加当作独立论文数。记录关键词更新、检索时点与覆盖盲区；从旧台账恢复时保留原查询、已排除文献和旧判定，只新增本次变化。

按 DOI、稳定数据库号、预印本与期刊对应关系去重；缺标识时用归一化题名、作者、年份复核。标记更正、撤稿、同数据集的多报告及版本间结论变化。优先次序依机制和条件的接近度；被引少、语言不同或尚未发表到期刊均不足以排除。只查题录用以初筛，阅读全文后再决定它能否推翻核心主张。对排除的强候选留一句理由。

## D　何时结束

快速初筛可在核实一篇足以覆盖具体主张的前作、或找到下一项会改变决策的核查后收尾，列出尚未覆盖的渠道。正式查新按以下规则进行并验收。

## E　按真实回包推进检索

1. **先定预算和停止条件。** 按主张需要，预留初次查询、换旧名/相邻概念、沿引文与具名基准再查的预算。用轮数、可检查结果数、可获取全文数或时间表达资源上限。缺省可先检查每次查询相关性最高的一页；若排序偏向高被引或新发表，再换时间窗或排序。muye 的流程每轮先看十条摘要、上限十轮；这些数值可作为运行配置，不能当作召回率。[原始逐轮策略](https://github.com/muye1112/skill/blob/fa7df033b3d51e2f8774f51a83e91b5aeecd4e55/skills/novelty-assessment/SKILL.md#L41-L48)
2. **留下调用凭据。** 每次实际调用搜索服务或运行检索脚本时，记录渠道、查询原式、字段/语法、筛选条件、时间、页码或游标、状态、返回条数和候选的稳定标识；可存获准保存的原始响应或结果导出，并给出路径。网页查询保留可复核的位置或链接。手工从已有文献导入的条目标“用户提供”或“追引取得”。编好查询但无可用工具时标“未执行”。工具真正返回零条、超时、限流、无权限和只读到搜索摘要分别记账。短暂故障可重试一次，仍失败就保留该渠道缺口并尝试另一可用渠道；不从模型记忆补写查询结果。[原始失败和零结果处理](https://github.com/stephenturner/skill-research-question-validator/blob/06fe29a993a3553e8948a6c98f4eb81c1fc60ddf/SKILL.md#L59-L70)
3. **检后决定下一轮。** 写“本轮新增的强竞争者 P… / 承接的主张 C… / 它暴露的旧名、基线或未读出处 / 下一条具体查询”。从直接竞争者抽取具名对照、同机制术语以及引用链，至少尝试覆盖前后向引文。返回大量无关结果时调整词义和字段；找回设计查询的种子只说明查询能命中熟悉文献。正式查新将独立挑战集与起草查询的种子分开，记录逐篇命中情况、漏检原因、修复和重跑的差异。条件允许时由另一位评阅人独立复核查询设计，注明评阅方式。没有第二位评阅人时如实标记自审。[原始检索策略审查](https://github.com/yananlong/codex-skills/blob/a9bad384ae7e04eea38ab5efb13529ae4b664575/research/research-systematic-literature-review/SKILL.md#L138-L168)
4. **把预算耗尽与覆盖完成分开。** 每条中央主张都有能命中的查询、最强竞争者及处理理由，决定性引用链已追到原始来源，修订查询没有引入新的高风险近邻，才可记录“本轮覆盖达到预定范围”。发现一篇直接反例，可提前结束受影响主张，其他主张分别继续。到预算上限仍无法读取关键全文、关键数据库受限或独立挑战样本遗漏，就冻结本轮已有记录，并按[正式查新的证据验收](extended-review.md#正式查新的证据验收)给出保留判断。[按直接对手扩展](https://github.com/Giovanni-Sforza/idea-survey-pipeline_claude/blob/7fa71ad0ef6dedcb5271c6bf69c343dddbc5a237/.claude/skills/idea-novelty/SKILL.md#L1047)
