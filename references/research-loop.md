# 把每轮反证落实到下一次查询与判断

正式查新的第一轮就立下反例标准。确定核心动作、研究对象、必要条件和输出量；只要找到哪种具名原文，就撤回哪一句话？先固定纳排条件。新增证据使标准需要改变时，保存新定义，并重新筛选会受影响的记录。

## 内层逐项找反例，外层决定是否改题

1. 从会改变决定的缺口里挑一项。写下主张编号、最可能使用的旧名称、最强竞争路线和要读的方法或图表。实际执行一轮搜索、追引或全文阅读。把渠道、原式、近邻编号、原始返回和失败情况写入档案。每条新线索说明“它比当前最强反例多覆盖了哪一项”。仅返回更多相同论文时，改用另一条引文链、学科库、部件名称或更早的术语。
2. 如果新前作已在同样条件下给出同样结果，收回相应首次声明并保留其它主张。只覆盖部件则检查组合的次序、共享条件和哪种非显然现象出现。如两种方法经换变量便等价，查原文证明和适用域。论文检索不能证明未执行步骤或模拟效果。
3. 针对争议，先让反方以**一个**最有力的前作组织反驳，写出题名、原文位置、操作、条件、结果；再把原始材料与这条质疑交给另一位读者，逐点区分“原文已解答”“只答了一部分”“证据仍不足”。记录两方身份与范围。同一执行者扮演两种角色时写作自查。这是对查新争议采用两步判读的改编。一般任务仍按[ARIS 审查规程](aris-review.md)完成独立审查。
4. 每批研究后以案件整体复盘。哪些竞争解释被排除？哪些措辞只能收窄？哪一项仍值得投入？若还有能够取得且足以翻转判断的来源，继续取证。已查过同一方向仍未改变结论时，先解释重复的原因，再决定扩词、换来源、缩小边界或收尾。停止依据写成实际覆盖和剩余风险。预设预算用尽会限制结论，找到一篇直接反例则已足以撤回它实际覆盖的主张。
5. 给用户当前判断、上一轮到本轮的变更以及触发下一步的条件。保持上游候选、缺口和来源编号的对应。需要导师判断时，将主张、最接近的前作、已否决措辞、尚存差异和可区分验证一起交接。需要发文章时给可引用的原文位置和不过度外推的句子。

## 两个容易混淆的决定

**哪些前作必须优先读全文？** 先看问题、核心机制、关键洞见和应用条件四处可能的重合。机制相同但对象不同、摘要没有讲清关键步骤、或近期同一窄分支正在处理同一问题，这三类都要保留为强候选。为每个优先候选写下它如何进入精读队列，在原文定位问题设置、动作和适用边界。记忆中想起的文章先核实身份再入列。首批可取三至七篇管理阅读量，决定性反例在首批之外就继续读。四项重合的数量只调阅读顺序。把最终差异写成一条审稿人能用同一原文和同一输出量核对的话。[ResearchStudio scoop-check](https://github.com/microsoft/ResearchStudio/blob/063f10088af49909e1a4a7ea8d29efe19633f34e/ResearchStudio-Idea/skills/scoop_check/SKILL.md)

**值得继续和已有重合分别怎样判断？** 新颖性先引用前作及定位，再独立判断问题重要程度、方法深度与自洽性、资源可得性以及该方法能否解决所说的问题。每项给理由和证据边界。只有初步构想时以论证和资源约束判断可行性。比较两个剩余构想时隐去名称与作者，以相同问题顺序分别评述，核查交换呈现次序后理由是否改变。即使其中一个得分更高，已核实的重复主张仍应撤回。[ResearchStudio idea-quality](https://github.com/microsoft/ResearchStudio/blob/063f10088af49909e1a4a7ea8d29efe19633f34e/ResearchStudio-Idea/evaluation/idea_quality/SKILL.md)

## 如何留住真正的变化

在有增量复查、审查意见或多轮搜索时，在案件目录执行以下命令。快照是轻量索引，原始查询和原文证据继续保留在案内。

```text
python "<skill>/scripts/compare_rounds.py" snapshot "<case>/dossier.json" "<case>/round-01.json"
python "<skill>/scripts/compare_rounds.py" compare "<case>/round-01.json" "<case>/dossier.json"
```

第一条在第一轮有可比较的资料后执行，拒绝覆盖已有快照。补检、精读或修订后执行第二条。报告逐条返回新增或撤回的主张、定义的改动、发生变化的前作或查询编号、前后判定，以及仍限制本轮结论的因素。定义换了必须重查覆盖边界。DOI 相同而原文解读变了，先复读该图或公式，再检查所有引用它的主张。变化只有查询记录时，说明本轮检索补了什么，是否找到新的实质反例。全无差异也不能由程序推出检索已穷尽。
